# VpnRunner

Одна кнопка **Run**:

1. подключает рабочий **Cisco** (через openconnect: логин, пароль и код Google Authenticator подставляются сами);
2. поднимает **VPN по подписке** (через sing-box; подписок может быть несколько);
3. раскидывает трафик по правилам:

| Куда идёт трафик | Через что |
|---|---|
| Рабочие подсети и домены | Cisco |
| Российские сайты (.ru, .рф, .su, список российских сервисов, российские IP) | напрямую |
| Ваши сайты с пометкой «Напрямую» | напрямую |
| Ваши сайты с пометкой «Через VPN» (сильнее правила для российских сайтов) | VPN |
| Всё остальное | VPN |

**Stop** выключает в обратном порядке: сначала VPN, потом Cisco.

Если вы **за границей** — вкладка «Из-за рубежа»: сначала российский VPN, Cisco — через него (см. [ниже](#из-за-рубежа)).

В строке меню (сверху) — значок-щит: серый — выключено, жёлтый — подключается, зелёный — работает. В его меню: «Включить», «Выключить», «Открыть окно», «Выход». Закрытие окна только прячет его — VPN продолжает работать; совсем выйти (с остановкой VPN) — «Выход» в меню значка.

## macOS

Все команды ниже — **на локальной машине (Mac), в Терминале**.

1. Установить openconnect и sing-box:
   ```sh
   brew install openconnect sing-box
   ```
2. Нужен JDK 17 или новее (у вас он есть, если стоит Android Studio).
3. Запустить из папки проекта:
   ```sh
   ./gradlew run
   ```
   Собрать .dmg:
   ```sh
   ./gradlew packageDmg
   ```
   Готовый файл: `build/compose/binaries/main/dmg/`.

При каждом Run macOS один раз спросит пароль администратора — без root нельзя создать VPN-интерфейсы.

## Windows

1. Установить OpenConnect (консольный клиент) — 64-битный установщик с официальной сборки:
   https://gitlab.com/openconnect/openconnect/-/jobs/artifacts/master/raw/openconnect-installer-MinGW64-GnuTLS.exe?job=MinGW64/GnuTLS
2. Скачать sing-box для Windows (`sing-box-<версия>-windows-amd64.zip`) со страницы релизов
   https://github.com/SagerNet/sing-box/releases и положить `sing-box.exe` в `%APPDATA%\VpnRunner\bin\`
   (или указать путь во вкладке Cisco → «Дополнительно»).
3. Нужен JDK 17+. Запуск — **на локальной машине (Windows), в PowerShell, в папке проекта**:
   ```powershell
   .\gradlew.bat run
   ```
   Собрать установщик:
   ```powershell
   .\gradlew.bat packageMsi
   ```
4. Программа должна работать **от имени администратора**. Если запустить без прав, на главной будет кнопка «Перезапустить от имени администратора».

## Первая настройка

**Подписки.** Вкладка «Подписки» → название + ссылка `https://…` → «Добавить подписку». Серверы появятся в списке на главной. «Авто» выбирает самый быстрый.

Если адрес подписки блокирует провайдер («нет соединения (таймаут)»), программа пробует скачать её через системный прокси и через локальные прокси `127.0.0.1:2080 / 10809 / 7890` (Throne, v2rayN, Clash). Для первого раза достаточно включить Happ или Throne и нажать «Обновить» — подписка сохранится, дальше Run работает и без них. Когда VPN запущен, адреса подписок всегда идут через VPN, и подписки обновляются автоматически после Run.

Программа передаёт сервису подписок идентификатор устройства (`x-hwid`, как Happ) — сервисы с лимитом устройств без него присылают вместо серверов заглушку «App not supported». Компьютер появится в списке устройств сервиса как «VpnRunner». Если сервис всё равно присылает заглушку, обычно лимит устройств исчерпан: удалите лишнее устройство в боте или личном кабинете.

**Cisco.** Вкладка «Cisco»:
- Сервер — то же, что вводите в AnyConnect.
- Логин, группа (если в AnyConnect есть выбор группы).
- Пароль → «Сохранить». Хранится в Связке ключей macOS / в зашифрованном виде (DPAPI) на Windows, не в файле настроек.
- Секрет Google Authenticator — скопируйте из TOTP Vault **секретный ключ** (строка вроде `JBSWY3DPEHPK3PXP`, параметр `secret=` из QR-кода) или целую ссылку `otpauth://…`. После сохранения программа показывает текущий код — он должен совпадать с кодом в TOTP Vault.
- Рабочие подсети (например `10.0.0.0/8`) и домены (например `corp.local`). Если оставить пустым — берутся подсети, которые присылает сервер.
  DNS Cisco спрашивается только про рабочие домены — присланные сервером (их видно в журнале при подключении) и указанные здесь; остальные имена до компании не доходят. Если внутренний сайт не открывается, добавьте его домен сюда. На macOS для каждого рабочего домена создаётся файл `/etc/resolver/<домен>` (помечен `# VpnRunner`, удаляется при Stop), остальные имена резолвит sing-box; если включён другой VPN (Happ), обычные имена может резолвить он. Если сервер присылает «весь трафик через Cisco», программа предупредит: тогда подсети нужно указать вручную.

**Правила.** Вкладка «Правила» → сайт → «Напрямую» или «Через VPN». Правило действует и на поддомены. Если VPN уже работает — нажмите «Применить» (Cisco при этом не переподключается).

## Рабочее время

Если на работе смотрят, когда включён рабочий VPN, программа следит за этим (будни, по Москве; часы — во вкладке Cisco, по умолчанию 09:00–18:00):
- на главной — карточка «Рабочий день»: когда сегодня подключился Cisco, сколько осталось до конца дня, обрывы;
- уведомления от значка: в 8:50, если Cisco не подключён; раз в 15 минут в рабочее время, если не подключён; при обрыве; в конце дня — «можно выключать»;
- Stop, «Выключить» и «Выход» до конца дня сначала спрашивают подтверждение.

Учёт хранится в `work-days.json` в папке настроек (60 дней). Праздники не учитываются — только выходные.

Пока VPN включён, компьютер и экран не засыпают (во сне Cisco отключается). Выключается во вкладке Cisco: «Не давать компьютеру засыпать». Закрытая крышка ноутбука без внешнего монитора всё равно усыпляет Mac, а выключение компьютера программа не предотвращает.

## Merge request в GitLab

Вкладка «GitLab» присылает уведомление от значка, когда в рабочем GitLab появляется новый merge request:
1. Откройте в браузере список MR проекта, настройте фильтры (например, не черновики, не мои, не одобренные мной) и скопируйте адрес — вида `https://gitlab.company.ru/group/app/-/merge_requests?draft=no&…`. Ссылок может быть несколько, по одной в строке.
2. Создайте личный токен с правами **read_api** (кнопка «Создать токен в GitLab» откроет нужную страницу) и сохраните его — он хранится в Связке ключей.
3. Включите «Уведомлять о новых merge request».

Проверка — раз в 2 минуты, пока подключён Cisco (GitLab во внутренней сети). О MR, которые уже были открыты при первой проверке ссылки, программа не уведомляет — только о новых; MR, снова попавший под фильтр (сняли черновик, сбросили одобрение), — тоже новость. Открытые MR видны списком во вкладке; по щелчку MR открывается в обычном браузере. Число на вкладке — сколько их сейчас.

## Списание времени в Jira

Вкладка «Jira» показывает ваши задачи спринта с оставшимся временем и списывает время через Tempo.
1. Откройте доску спринта в браузере и скопируйте адрес — вида `https://jira.company.ru/secure/RapidBoard.jspa?rapidView=2827&projectKey=SYRAX`.
2. Создайте в Jira личный токен (Профиль → Personal Access Tokens; кнопка «Создать токен в Jira» откроет эту страницу) и сохраните его — он хранится в Связке ключей.
3. Если Jira подписана сертификатом компании, программа покажет его название и отпечаток SHA-256 — нажмите «Доверять», если это ваш корпоративный сертификат. Доверие действует только для запросов программы к Jira.

**Неделя** (открывается по умолчанию) — таблица как в Tempo: строки — задачи, столбцы — дни недели (выходные — если в них что-то списано или включено «Сб, Вс»), в ячейке — часы за день. Списывать можно на любой день — прошлый, сегодняшний или будущий. Щёлкните ячейку, введите `2`, `1.5`, `1h 30m` или `45m` и нажмите Enter (или просто перейдите в другую ячейку) — списание сохранится; Esc — отменить. Изменить число — время списания поменяется; очистить ячейку или ввести `0` — списания за этот день удалятся. Если в ячейке несколько списаний, уменьшать их нужно в виде «День». Первой строкой — контейнер спринта, дальше задачи спринта на вас, задачи в работе, из MR и те, на которые на этой неделе уже списывали. Внизу — сколько списано за каждый день: зелёным — норма набрана, красным — прошедший будний день с недобором. ‹ › — соседние недели, «Сегодня» — вернуться, «Дата…» — календарь, чтобы перейти к любому дню. Если в Tempo есть обязательные атрибуты (например «Тип работ»), выберите их над таблицей — они подставятся во все списания из неё. Комментарий у списаний из таблицы — название задачи.

**День** (или щелчок по дню в заголовке таблицы) — подробный вид:
- выбор спринта (по умолчанию — активный) и дня: ‹ ›, «Сегодня», «Дата…» — любой день, в том числе будущий;
- сколько списано за день из нормы (8 ч, меняется в настройках вкладки);
- **«Спринт · на мне»** — задачи спринта на вас (без подзадач): осталось по оценке Jira, сколько списано и из какой оценки; красным — списано больше оценки;
- **«Вне спринта»** — ваши задачи в работе и задачи из ваших открытых MR в GitLab (ключ вида `SYRAX-123` в названии MR или ветки; нужен настроенный GitLab). Каждая задача — один раз, откуда она — подписано;
- **«Другая задача»** — чтобы списать на задачу не из списка (из закрытого спринта, не на вас, с другой доски): вставьте ключ (`SYRAX-1234`) или ссылку на задачу и нажмите «Добавить». Задача появится в «Вне спринта» с меткой «добавлена вручную» и останется там, пока вы её не уберёте («Убрать» в форме задачи; на списания это не влияет);
- список списаний за день — с удалением.

Щелчок по задаче раскрывает форму: время (кнопки 15м / 30м / 1ч / 2ч / «Остаток дня» или вручную: `1h 30m`, `45m`, `1.5`), комментарий (необязательный — пустой заменяется названием задачи) и «Останется» — новая оставшаяся оценка, по умолчанию «было − списано». Если в Tempo есть обязательные атрибуты (например «Тип работ»), они тоже в форме; выбранное значение запоминается.

**Контейнер спринта.** Галка «Контейнер спринта» в форме задачи (вид «День»): на эту задачу ставится по 2 ч (меняется в настройках) в рабочие дни этого спринта — только в дни, где на неё ещё ничего не списано (ни программой, ни вручную).
- **Сам** — каждый будний день спринта, начиная с дня отметки и по сегодня. По умолчанию — только в дни, когда был включён Cisco (отпуск и больничный не заполнятся); галка «во все будни» под таблицей — независимо от Cisco. О каждом автосписании — уведомление.
- **Кнопками** под таблицей недели: «На неделю» и «На спринт» — проставить 2 ч на все незаполненные будни показанной недели или всего спринта, в том числе будущие. Перед списанием программа покажет список дней. Праздники не учитываются — только суббота и воскресенье: если в спринте праздник, очистите его ячейку.

Когда спринт закончится, отметьте контейнер нового спринта.

За 30 минут до конца рабочего дня, если сегодня списано меньше нормы, придёт напоминание. Данные обновляются раз в 10 минут, пока подключён Cisco (Jira во внутренней сети), и по кнопке «Обновить».

## Из-за рубежа

Сервер Cisco не пускает зарубежные адреса. Вкладка «Из-за рубежа» → «Я за рубежом» — и Run работает так:

1. берёт российский сервер из подписок: «Авто» — все серверы с 🇷🇺 / RU / «Россия» / «Москва» в названии (самый быстрый), или выбранный вручную;
2. узнаёт его адрес через DNS-over-HTTPS (местный провайдер не видит имён) и включает **kill switch**;
3. поднимает российский VPN и **проверяет по факту**, что снаружи виден российский адрес (ipinfo.io / ifconfig.co / ip-api.com). Не Россия или сервер не отвечает — Cisco не подключается, программа говорит, что видно;
4. подключает Cisco **только через российский VPN** (openconnect с `--proxy`, без DTLS). Напрямую он не может подключиться в принципе — даже если российский VPN упал, Cisco будет ждать, а не пойдёт со своего адреса;
5. поднимает основной VPN: весь остальной трафик — через российский VPN (или, если выключить «Весь трафик через российский VPN», через него только Cisco и российские сайты, а остальное — напрямую).

Что не утекает:

| | |
|---|---|
| Адрес | сервер Cisco видит только российский адрес; при kill switch и сайты не увидят зарубежный, если VPN оборвётся |
| DNS Cisco | спрашивается только про рабочие домены — как и дома |
| Имя сервера Cisco | резолвит российский сервер, местный DNS о нём не узнаёт |
| Остальной DNS | только зашифрованный (DoH): через российский VPN, для сайтов «напрямую» — к 1.1.1.1 |
| IPv6, обычный DNS (порт 53) мимо туннелей | закрыты kill switch |

**Kill switch** (macOS) — правила pf в своём якоре `com.apple/250.VpnRunner` (сам `/etc/pf.conf` не меняется): наружу можно только через туннели sing-box и Cisco и к адресам российских серверов (плюс локальная сеть и DHCP). Включается при Run, снимается при Stop. Если программа остановилась нештатно и блокировка осталась, на главной будет кнопка «Снять блокировку» (или просто нажмите Run). Журнал — `run/killswitch.log`. На Windows kill switch пока нет: Cisco и там подключается только через российский VPN, но остальной трафик при обрыве пойдёт напрямую.

Ограничения: Cisco работает по TCP (DTLS через прокси не ходит) — немного медленнее. Смена настроек этой вкладки применяется после Stop → Run. Если российский сервер в подписке не работает, Run остановится с сообщением «Российский VPN не работает» — выберите другой сервер.

## Вкладка «Браузер»

> Сейчас вкладка скрыта (`BrowserEngine.TAB_ENABLED = false`): ссылки на MR и задачи открываются в обычном браузере, программа не перезапускается на JetBrains Runtime. Всё ниже — на случай, когда её вернут.

Встроенный браузер (Chromium) — например, чтобы держать Jira внутри программы. Адресная строка, назад/вперёд, кнопка «В браузере»; последняя страница и вход на сайты сохраняются (кэш и куки — в `browser/` в папке настроек).

Ему нужна **JetBrains Runtime 17 с JCEF** — программа запускается на ней. Установка на Mac (Apple Silicon; для Intel замените `aarch64` на `x64`):
```sh
curl -L -o /tmp/jbr.tgz https://cache-redirector.jetbrains.com/intellij-jbr/jbrsdk_jcef-17.0.14-osx-aarch64-b1367.22.tar.gz
tar xzf /tmp/jbr.tgz -C ~/Library/Java/JavaVirtualMachines
```
`./gradlew run` найдёт её сам (`~/Library/Java/JavaVirtualMachines/jbrsdk_jcef-17*`), другой путь — `./gradlew run -Pjbr.jcef.home=<…>/Contents/Home`. Без неё программа работает как обычно, а вкладка подскажет, что установить. Собранный `.dmg` с браузером не проверялся.

Из Android Studio / IntelliJ можно запускать конфигурацию **VpnRunner** (Gradle-задача `run`, лежит в `.run/`) или зелёную стрелку у `main` в `Main.kt`. Стрелка запускает программу на Java самой IDE, в которой нет Chromium, поэтому программа сразу перезапускается на установленной JetBrains Runtime с JCEF (в окне «Run» будет строка «перезапуск на jbrsdk_jcef-…»). Отладчик IDE при этом к программе не подключается — для отладки браузера используйте конфигурацию **VpnRunner**.

Если страница не открывается, а над ней написано «компьютер не доверяет сертификату сайта», значит Mac не доверяет корневому сертификату компании (например, вход через `id.domrf.ru` подписан «DOMRF Root Certification Authority»). Обычный браузер в таком случае показывает предупреждение, а встроенный просто не открывает страницу. Установите корневой сертификат, полученный от IT:
```sh
security add-trusted-cert -r trustRoot -k ~/Library/Keychains/login.keychain-db <файл сертификата>
```
или вручную: двойной щелчок по файлу → «Связка ключей» → сертификат → «Доверие» → «Всегда доверять». После этого перезапустите программу.

## Где что лежит

| | macOS | Windows |
|---|---|---|
| Настройки | `~/Library/Application Support/VpnRunner/settings.json` | `%APPDATA%\VpnRunner\settings.json` |
| Уже показанные merge request | `~/Library/Application Support/VpnRunner/gitlab-seen.json` | `%APPDATA%\VpnRunner\gitlab-seen.json` |
| Сертификат Jira, которому вы доверились | `~/Library/Application Support/VpnRunner/jira-ca.pem` | `%APPDATA%\VpnRunner\jira-ca.pem` |
| Журналы, конфиг sing-box | `~/Library/Application Support/VpnRunner/run/` | `C:\ProgramData\VpnRunner\run\` |
| Из-за рубежа: цепочка, kill switch | `run/chain.json`, `run/chain.log`, `run/killswitch.log` | `run\chain.json`, `run\chain.log` |

Журналы openconnect и sing-box (и российского VPN в режиме «из-за рубежа») также видны во вкладке «Журнал».

## Ограничения

- **Другой VPN (Happ и т.п.)** можно не выключать. Такие программы отправляют частные сети (`10.0.0.0/8` и др.) мимо себя через Wi-Fi и этим перебивают маршруты Cisco — VpnRunner при подключении и затем каждые ~10 с забирает рабочие подсети обратно на Cisco, а при отключении возвращает как было (`run/route-fix.log`).
- **Смена сети** (дом → офис, раздача с телефона): старые маршруты к серверу Cisco через прежнюю сеть убираются сами при запуске и остановке — иначе Cisco не подключился бы («Can't assign requested address»). Если sing-box остановится сам (например, при сне Mac), он перезапускается.

- **xhttp.** sing-box не поддерживает транспорт xhttp. Если у сервиса есть только такие серверы, они будут пропущены (в журнале будет написано, сколько и почему).
- **Остановка на Windows** завершает процессы принудительно: интерфейсы исчезают вместе с процессами, но сервер Cisco не получает «до свидания» — сессия на его стороне закроется по таймауту.
- **macOS:** скрипт-супервизор с правами root запускает файлы из вашей папки `Application Support`. Так же устроены Throne и другие клиенты; если на Mac есть недоверенные программы под вашим пользователем, это стоит учитывать.
- Списки российских сайтов и IP программа скачивает напрямую с GitHub перед запуском VPN и обновляет раз в 3 дня (`rules/` в папке настроек). Если GitHub недоступен и копии ещё нет, sing-box скачивает их сам через VPN.

## Как устроено

Подробная документация — в [docs/](docs/README.md): устройство по вкладкам и потокам ([ARCHITECTURE.md](docs/ARCHITECTURE.md)), все настройки и файлы ([SETTINGS.md](docs/SETTINGS.md)), разбор ошибок ([TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)).

- `core/` — без зависимостей: разбор подписок (vless, vmess, trojan, shadowsocks, hysteria2), генератор конфига sing-box, TOTP (RFC 6238).
- `platform/` — запуск openconnect и sing-box, обёртка над vpnc-script для раздельного туннелирования Cisco, хранение секретов.
- `ui/` — интерфейс на Compose Desktop.
