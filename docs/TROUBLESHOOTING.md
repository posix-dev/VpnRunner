# Если что-то не работает

Сообщение программы → почему так бывает → что делать. Где смотреть подробности: вкладка «Журнал»
(«Программа», «Cisco», «sing-box», «Российский VPN») и файлы в `run/` ([SETTINGS.md](SETTINGS.md#папка-запуска-rundir)).

## Запуск

| Сообщение | Причина | Что делать |
|---|---|---|
| «Не найден openconnect / sing-box / vpnc-script — укажите путь» | бинарника нет в Homebrew, PATH и `appDir/bin` | `brew install openconnect sing-box` или путь во вкладке Cisco → Дополнительно |
| «Отменено: не введён пароль администратора» | отменён запрос macOS | Run ещё раз и ввести пароль Mac |
| «Программа должна быть запущена от имени администратора» | Windows без прав | кнопка «Перезапустить от имени администратора» на главной |
| «Добавьте хотя бы одну подписку» / «Не удалось загрузить подписки» | нет подписок или ни одна не скачалась и нет кэша | вкладка «Подписки»; если адрес блокирует провайдер — включить на время другой VPN-клиент и «Обновить», или вставить содержимое вручную |
| Вместо серверов «App not supported» | у сервиса исчерпан лимит устройств (HWID) | удалить лишнее устройство в боте / личном кабинете сервиса |
| Вкладка «Браузер» (сейчас скрыта): «нужна Java „JetBrains Runtime с JCEF“» | программа запущена не на JBR с JCEF, а JBR с JCEF не найдена в `~/Library/Java/JavaVirtualMachines/jbrsdk_jcef-17*` (иначе программа перезапустилась бы на ней сама), либо это Windows | установить JBR — README, «Вкладка Браузер»; или запускать конфигурацию **VpnRunner** (`.run/`, Gradle-задача `run`) / `./gradlew run -Pjbr.jcef.home=…` |
| Вкладка «Браузер»: страница пустая, сверху «компьютер не доверяет сертификату сайта» | сайт (часто страница входа, например `id.domrf.ru`) подписан корпоративным центром сертификации, которому Mac не доверяет; проверить: `curl https://<сайт>` → `SSL certificate problem` | установить корневой сертификат компании в Связку ключей с «Всегда доверять» (README, «Вкладка Браузер») и перезапустить программу |

## Cisco

Текст после «Cisco не подключился:» подбирает `VpnController.explainCiscoFailure` по журналу openconnect.

| Сообщение | Причина | Что делать |
|---|---|---|
| «сервер не принял логин, пароль или код…» | неверные данные или код TOTP | логин — как в AnyConnect; сверить «Текущий код» во вкладке Cisco с приложением-аутентификатором; при расхождении сохранить секрет заново |
| «сервер спрашивает код отдельным полем» / «…второй пароль (код)» | не тот режим ввода кода | переключатель «Код вводится вместе с паролем» / сохранить секрет TOTP |
| «сертификат сервера не прошёл проверку» | самоподписанный сертификат (в журнале «Certificate from VPN server … failed verification») | вписать `pin-sha256:…` из журнала Cisco в поле отпечатка. Строка «Server certificate verify failed» при указанном отпечатке — норма |
| «…остался маршрут через сеть, к которой Mac уже не подключён» (в журнале «Can't assign requested address») | Cisco был подключён в другой сети, vpnc-script не убрал маршрут к серверу | нажать Run ещё раз: мёртвые маршруты убираются при остановке и запуске (`run/route-fix.log`). Вручную: `netstat -rn -f inet \| grep UGHS`, затем `sudo route -n delete -host <адрес>` |
| «не удалось соединиться с сервером Cisco» | нет интернета или неверный адрес сервера | проверить сеть и адрес во вкладке Cisco |
| «рабочие адреса Cisco идут не через Cisco, а через …» | другой VPN держит маршруты частных сетей | выключить другой VPN и Run |
| «⚠ Рабочее имя … не получило внутренний адрес» | системный DNS перехватывает другая программа | выключить другой VPN; проверить рабочие домены во вкладке Cisco |
| «⚠ Сервер Cisco хочет пускать через себя ВЕСЬ трафик» | сервер прислал full tunnel | указать рабочие подсети во вкладке Cisco |
| «DNS Cisco не используется: сервер не прислал рабочие домены» | split-DNS не настроен на сервере | вписать рабочие домены во вкладке Cisco |
| Внутренний сайт открывается с ошибкой сертификата | Mac не доверяет корневому сертификату компании | установить его в Связку ключей, «Всегда доверять» |

## VPN (sing-box)

| Сообщение | Причина | Что делать |
|---|---|---|
| «VPN (sing-box) не запустился» + строки журнала | ошибка конфига или сервера | смотреть строки в сообщении и журнал sing-box; для проверки конфига — `sing-box check -c run/config.json` |
| «Не удалось переключить сервер на лету» | Clash API не ответил | Stop → Run |
| В журнале «пропущено: … xhttp» | sing-box не умеет xhttp | использовать другие серверы |

## Из-за рубежа

| Сообщение | Причина | Что делать |
|---|---|---|
| «Не нашёл российских серверов…» | ни одно название не похоже на российское | выбрать сервер вручную во вкладке «Из-за рубежа» |
| «Не удалось узнать адрес российского сервера» | DoH, кэш и системный DNS не ответили | проверить интернет, Run ещё раз (после первого удачного запуска адрес запоминается) |
| «Российский VPN (sing-box) не запустился» | цепочка упала при старте (занят порт 2081, ошибка конфига) | журнал «Российский VPN»; `lsof -iTCP:2081` |
| «Российский VPN не работает: через него не открывается ни один сайт» | сервер недоступен или блокируется; в журнале часто `reality verification failed` | выбрать другой российский сервер. Cisco в этом случае не подключается — так и задумано |
| «Выход российского VPN — не в России (…)» | сервер на деле в другой стране | выбрать другой сервер |
| «не удалось подключиться к серверу через российский VPN» | openconnect не прошёл через прокси | проверить адрес сервера Cisco; сменить российский сервер |
| Нет интернета совсем, VPN выключен | kill switch остался после сбоя | кнопка «Снять блокировку» на главной или просто Run. Вручную: `sudo pfctl -a com.apple/250.VpnRunner -F all` |
| Нет интернета, VPN включён | российский VPN оборвался — kill switch работает | дождаться восстановления (цепочка и sing-box перезапускаются сами) или Stop |
| Cisco медленнее, чем дома | через прокси нет DTLS (UDP), только TCP | ожидаемо |

## GitLab

| Сообщение | Причина | Что делать |
|---|---|---|
| «Проверю, когда подключится Cisco» | GitLab во внутренней сети, Cisco не подключён | Run; или «Проверить сейчас» — проверит без Cisco |
| «GitLab не принял токен» | токен неверный, отозван или истёк | создать новый (права read_api) и сохранить |
| «проект не найден или у токена нет к нему доступа» | опечатка в ссылке или у токена нет прав read_api | скопировать ссылку из браузера заново; токен — с read_api |
| «GitLab недоступен / не ответил» | нет Cisco или DNS рабочих доменов | подключить Cisco; домен GitLab — в «Рабочие домены» вкладки Cisco |
| Уведомлений нет, хотя MR есть | эти MR уже были открыты при первой проверке ссылки | так задумано: уведомления — только о новых; список открытых — во вкладке |

## Jira

| Сообщение | Причина | Что делать |
|---|---|---|
| «Обновлю, когда подключится Cisco» | Jira во внутренней сети, Cisco не подключён | Run; или «Обновить» — без Cisco |
| Карточка «подписана сертификатом … — его нет среди известных центров» | Jira подписана корпоративным центром сертификации | сверить отпечаток SHA-256 с IT и нажать «Доверять» (сохраняется в `jira-ca.pem`) |
| «сертификат Jira не подходит к адресу» | в ссылке на доску не то имя сервера (например, IP) | скопировать ссылку на доску из браузера заново |
| «Jira не приняла токен» | токен неверный, отозван или истёк; или ссылка ведёт не на Jira | создать новый Personal Access Token и сохранить |
| «Jira недоступна / не ответила» | нет Cisco или DNS рабочих доменов | подключить Cisco; домен Jira — в «Рабочие домены» вкладки Cisco |
| «Не удалось списать … : Jira ответила 400» | Tempo отклонил списание (закрытый период, обязательный атрибут, нет прав на задачу) | текст ошибки — от Tempo; проверить в самой Jira |
| Под контейнером «Для автосписания нужен атрибут …» | в Tempo обязательный атрибут, значение ещё не выбрано | один раз списать вручную на любую задачу, выбрав значение |
| «Задача … не найдена или у вас нет к ней доступа» (поле «Другая задача») | опечатка в ключе или задача в проекте, куда у вас нет доступа | проверить ключ, открыв задачу в браузере |
| «… несколько списаний — уменьшите нужное в виде «День»» | в ячейке недели несколько списаний, а число уменьшили | щёлкнуть по дню в заголовке таблицы и удалить лишнее списание в списке за день |
| «Выберите «…» над таблицей» | в Tempo обязательный атрибут, для таблицы значение не выбрано | выбрать значение над таблицей недели |
| Контейнер не списался за день | в этот день Cisco не включали (а «во все будни» не отмечено), уже было списание на контейнер, день — выходной, или день раньше отметки контейнера | кнопка «На неделю» / «На спринт» под таблицей или вручную в ячейке |
| Контейнер списался на праздник | праздники программа не знает — только субботу и воскресенье | очистить ячейку этого дня в таблице недели |

## Рабочее время

Напоминания приходят уведомлениями от значка в строке меню. Время — по Москве, праздники не учитываются; учёт — `work-days.json`. Пока VPN включён, программа не даёт компьютеру и экрану засыпать (`KeepAwake`, переключатель «Не давать компьютеру засыпать» во вкладке Cisco). Всё равно засыпает — проверьте `pmset -g assertions | grep caffeinate` (должны быть `PreventUserIdleDisplaySleep` и `PreventUserIdleSystemSleep`); закрытая крышка без внешнего монитора усыпляет Mac в любом случае. Во сне Cisco отключается, и это видно на работе.

## Чем ещё полезно

```sh
sudo pfctl -a com.apple/250.VpnRunner -s rules     # текущие правила kill switch
scutil --dns | head -40                             # какой DNS реально у системы
route -n get 10.0.0.1                               # через какой интерфейс идёт рабочий адрес
ls /etc/resolver/                                   # рабочие домены (файлы с # VpnRunner)
curl -x http://127.0.0.1:2081 https://ipinfo.io/json  # из-за рубежа: что видно через цепочку
```
